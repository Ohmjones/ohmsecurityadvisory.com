What was covered.

Defender Takeaways

Three things worth changing Monday morning.

If you do nothing else with what was in the talk, do these three. Each is concrete, scoped to a team, and works against the attack class the talk covers.

DT-1
Out-of-band verification for credential and high-privilege actions
Help desk procedure
A phone call to a help desk is in-band — the same channel the attacker is on. Out-of-band means a callback to a number on file with HR, a manager confirmation through an independent channel, or an MFA push to a known device. Mandate it for credential resets, MFA resets, and any high-privilege account change. The agent should never be the sole verifier. The script the talk demonstrates defeated everything inside the call. Outside it, the same script falls apart.
DT-2
Agent training that specifically covers AI voice and LLM-assisted pretexting
Training program
Generic social engineering awareness doesn't cover what's happening now. Agents need to hear cloned voice samples, see what an LLM-written pretext reads like, and know that "this feels off, let me call you back" is a sanctioned response — not a career risk. Authority limits need to be written down. Pressure tactics need to be named. The talk's call worked because the agent had no playbook for what was actually happening.
DT-3
Time detection-to-response against realistic attacker escalation
Detection engineering · IR
Detection alone doesn't help if the attacker pivots faster than your triage window. Walk your runbooks against a five-minute escalation timeline, not a tabletop scenario. Where can a credential be used between issuance and revocation? Which controls block lateral movement during the window where the alert is sitting in a queue? The answer reveals whether your detection program is actually defending anything.
